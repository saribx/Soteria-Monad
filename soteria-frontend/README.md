# Soteria operations console

The incident command UI for Soteria. It opens on a live 3D map, where each
train stands on the real track it is on, with its exact wagons, the damage and
the obstruction. Next to the map it shows what the operator needs for the
incident in view: the Soteria decision, the train's consist and the line status.
Fleet, incident and analytics views sit on top of the same data. A second page,
`console.html`, replays the agent event stream.

## Run

```shell
npm install
echo "VITE_MAPBOX_ACCESS_TOKEN=pk...." > .env.local
npm run dev        # http://localhost:5173 (agent console: /console.html)
npm run build      # type check + production build into dist/
npm run preview    # serve the production build
```

**Mapbox token.** A free public token from [mapbox.com](https://account.mapbox.com)
(50k map loads a month) unlocks Mapbox Standard: 3D buildings, landmark models,
3D trees and terrain, with satellite imagery underneath. `.env.local` is
git-ignored. For a deployment, restrict the token to your domains in the Mapbox
account. Without a token the map falls back to keyless satellite imagery (Esri),
AWS terrain and OpenStreetMap building extrusions.

## Where the data comes from

| Data | Source | Generated by |
|---|---|---|
| Train, wagons, incident, damage | `../data/<case>/` (shared with the backend) | hand-written, validated by `scripts/validate_data.py` |
| Location, route, journey, livery, obstruction model, initial camera | `../data/scenarios.json` | hand-written |
| Soteria decision, consensus, event stream | `src/data/soteria.json` | `scripts/export_frontend.py` from the recorded runs in `view/fixtures/` |
| Track centre lines, tunnels, bridges, stations | `src/data/railCorridors.json` | `scripts/fetch-rail-corridors.mjs` (OpenStreetMap via Overpass) |

`src/data/scenarios.ts` joins the first two, and `src/data/mockFleetData.ts`
builds the assets, routes and incidents from them. The map, the fleet tab and
the incident feed all derive from those, so nothing is copied into components.

## Changing a scenario

1. **Facts** (train, wagons, damage, incident) in `../data/<case>/`, then from the
   repository root:

   ```shell
   uv run python scripts/validate_data.py
   uv run python scripts/record_run.py <case>
   uv run python scripts/export_frontend.py
   uv run python scripts/export_frontend.py --out soteria-frontend/src/data/soteria.json
   uv run pytest -q
   ```

   The wire proof searches every answer for raw values. Pick values that are not
   substrings of field names, for example not `available`, which is a substring
   of `replacement_available`.

2. **Geography or presentation** in `../data/scenarios.json`: location label,
   route, journey times, livery, obstruction model, `initial_focus`. If the
   `corridor` block changed (track sources, where the locomotive stands, how far
   the line reaches):

   ```shell
   node scripts/fetch-rail-corridors.mjs <route id>
   ```

   A corridor is stitched from OSM main-line track, taken from bounding boxes
   and/or railway relations. The script walks from `anchor` towards `toward`,
   bridges small gaps in the OSM data and drops mis-ordered nodes. Overpass
   responses are cached in `scripts/.overpass-cache/`, so moving a train
   re-stitches in about a second.

## The map

- **Basemap:** Mapbox Standard (3D buildings, trees, landmarks) with the Mapbox
  satellite layer, lighting preset *night* by default.
- **Rail network:** OpenStreetMap railways and stations for the whole world from
  [OpenFreeMap](https://openfreemap.org) vector tiles, keyless.
- **Corridors:** the incident corridors in full detail at close zoom: ballast,
  sleepers, and two rails at standard gauge. The track a train has already
  travelled is grey, the track still ahead to its destination glows blue. The
  origin and destination stations are pinned.
- **Trains:** fill extrusions that follow the track curve: a locomotive in its
  operator's livery plus one car per wagon (box wagon, reefer, tank wagon).
  Damaged wagons pulse red, and each shows its damage as the incident report
  describes it (`damageKind()` in `src/map/trainModel.ts` reads the
  description): a reefer unit torn off and lying on the ballast, a side wall
  ripped open with cargo spilling out, a crushed tank dome with a spill, a
  concertinaed coupling end. The obstruction is modelled in 3D (a fallen tree
  with the overhead line it brought down, a rockfall boulder, a collapsed
  gantry), and its stretch of track glows red.
- **Controls:** a click on a train card flies to the train and follows it while
  it moves. On the trackpad, two-finger rotation turns the map in Safari. Chrome
  and Firefox do not expose that gesture, so there a horizontal two-finger swipe
  rotates.

The code lives in `src/map/`: `railGeometry.ts` measures a corridor in metres,
`trainModel.ts` builds the cars, `soteriaLayers.ts` holds the sources and
layers. `src/components/map/InteractiveMap3D.tsx` wires them to the React state.

## Layout

```
src/
  components/   command (bottom panel), fleet, incidents, analytics, layout, map, modals
  context/      FleetContext: assets, incidents, selection, simulation
  data/         scenarios.ts, mockFleetData.ts, generated soteria.json + railCorridors.json
  map/          geometry, train model and layers of the 3D map
  console/      agent live console (console.html)
  styles/       tokens, glass and layout styles
scripts/        fetch-rail-corridors.mjs
```
